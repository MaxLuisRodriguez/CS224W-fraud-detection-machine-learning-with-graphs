\textbf{Motivation.} Before each call, a sales rep's AI research agent can look up a prospect's recent activity, company details, and buying signals. Lookups cost enrichment credits, LLM tokens, or latency, so no team researches every prospect deeply: the real decision is \emph{which lookups to make for the whole call list} within a budget. That is a graph problem: sales data are linked tables, and prospects on one list often touch the same accounts and events (Figure~\ref{fig:calllist}), which couples them twice. \emph{Shared entities}: enriching one event informs every prospect connected to it. \emph{A shared cutoff}: a rep calls only the top $K$, so a lookup matters only if it can move a prospect across that line, which depends on everyone else's scores. Researching prospects one at a time ignores both.

\textbf{Research question and novelty.} Given a call list of $N$ prospects and a budget of $B$ lookups, which lookups should an agent make so a graph neural network (GNN) ranks the list best? Beyond applying an existing GNN, I define retrieval-budgeted prediction on relational data, extend a relational GNN to partial neighborhoods, and learn a policy that credits each lookup for every prospect it informs.

\textbf{Datasets (public).} I use three tasks from RelBench~\cite{robinson2024relbench}, a benchmark of real relational databases with temporal splits (Table~\ref{tab:data}): \texttt{user-ignore} (will a user ignore more than two event invitations next week?), \texttt{user-clicks} (will a user click more than one ad in four days, a sign of intent?), and \texttt{driver-top3}, a small development task. All are public on Hugging Face (\texttt{stanford-star/relbench-v1}, no login needed) and come from two Kaggle competitions.\footnote{Event Recommendation Engine Challenge and Avito Context Ad Clicks, on kaggle.com.}

\textbf{Metrics.} AUROC, RelBench's metric, is the chance a random positive outranks a random negative. Since a rep makes only the first calls, I also report average precision and Precision@$K$, the share of positives among the top $K = \lceil 0.1N \rceil$ (13 of 128), averaged over 200 random lists. Budgeted results are \emph{frontiers} (metric vs.\ lookups per prospect), summarized by area; test data is used once.

\textbf{Why these datasets.} \emph{Headroom}: on both primary tasks the GNN beats a model that sees only the target's row (+0.031 and +0.118 AUROC), so fetched context matters; I exclude tasks without this gap (e.g., \texttt{user-repeat}). \emph{Contrasting sharing}: on \texttt{rel-event}, 34\% of the events a list touches are shared and a shared cache saves 38\% of event lookups, versus 0.1\% of \texttt{rel-avito} ads, so I can test when joint planning pays.

\section{Graph ML techniques}

\textbf{Model.} I use relational deep learning (RDL)~\cite{fey2024rdl}, built with RelBench and PyTorch Geometric (PyG)~\cite{fey2019pyg}. Each table row is a node $v$ with table type $T(v)$, features $x_v$ (its columns), and timestamp $\tau(v)$; each primary--foreign-key link is an edge in both directions, typed by its relation $r \in \mathcal{R}$. To score a prospect at time $t$, PyG's \texttt{NeighborLoader} samples up to 128, then 64, neighbors per relation over two hops, from rows dated at or before $t$. A row starts as $h_v^{(0)} = \mathrm{Enc}_{T(v)}(x_v) + \phi(t - \tau(v))$, a per-table encoder of its columns plus an encoding $\phi$ of its age, so recency matters. Two heterogeneous GraphSAGE layers~\cite{hamilton2017sage} then update each node from its neighbors $\mathcal{N}_r(v)$ per relation:
\begin{equation}
  h_v^{(\ell+1)} = \mathrm{ReLU}\Big(\mathrm{LN}\Big(\textstyle\sum_{r \in \mathcal{R}} \big[ W^{(\ell)}_{r,1} h_v^{(\ell)} + W^{(\ell)}_{r,2} \sum_{u \in \mathcal{N}_r(v)} h_u^{(\ell)} \big]\Big)\Big).
\end{equation}
Each relation has its own weights (``attended'' vs.\ ``friend of'') and LN is layer normalization; after two layers, a linear head maps the prospect's vector to a probability $f_\theta(q)$.

\textbf{Partial retrieval (my extension).} The agent sees only $O$, the rows fetched so far (always including the call list). Other rows are dropped from the graph or kept as \emph{stubs}, known to exist but unfetched:
\begin{equation}
  \tilde h_v^{(0)} = m_v\, h_v^{(0)} + (1 - m_v)\, e^{\mathrm{mask}}_{T(v)}, \qquad m_v = \mathds{1}[v \in O].
\end{equation}
A stub gets a learned per-table placeholder, so the model can tell ``unfetched'' from ``absent.''

\textbf{Lookup policies.} A lookup $a$ costs one unit: \emph{pull} a prospect's rows from one table, or \emph{enrich} an entity that fetched rows point to. For a list $Q = \{q_1, \dots, q_N\}$ with labels $y_i$, a policy $\pi$ picks lookups in sequence; with $O^\pi_B$ its rows revealed after $B$ lookups and $M$ a ranking metric, I seek $\max_\pi \mathbb{E}[M(f_\theta(Q \mid O^\pi_B), y)]$. Its \emph{batch value} is the list-wide drop in cross-entropy $\ell$:
\begin{equation}
  V(a \mid O) = \textstyle\sum_{i=1}^{N} \big[ \ell\big(f_\theta(q_i \mid O), y_i\big) - \ell\big(f_\theta(q_i \mid O \cup \{a\}), y_i\big) \big].
\end{equation}
Summing credits a shared entity for every prospect it informs, which per-prospect methods miss. $V$ needs labels, so I compute it on training lists and train a second GNN to predict it from the revealed graph; at test time the policy takes the highest-predicted lookup, then re-scores.

\textbf{Why these models fit.} Message passing uses the database's links, not hand-built features; temporal sampling prevents leakage; shared entities are shared nodes; and one model serves any budget.

\textbf{Related work.} RDL assumes full data; KumoRFM-2~\cite{hudovernik2026kumorfm2} and STEER~\cite{mohamed2026steer} drop or prune context and missing-feature GNNs impute~\cite{rossi2022fp}, but none chooses costed lookups. Active feature acquisition is per instance~\cite{norcliffe2025sefa,valancius2024aco,feng2026brig} or per cohort without shared entities~\cite{rheude2025cama}, the closest graph method values node queries independently~\cite{zhou2026scout}, and collective active inference acquires labels, not rows~\cite{bilgic2010active}.

\section{Evaluation plan and preliminary results}

\textbf{Baselines, hypotheses, and analyses.} Baselines: random, case-local round-robin ($B/N$ lookups each), uncertainty-first, coverage (most-shared first), per-prospect acquisition~\cite{norcliffe2025sefa,valancius2024aco}, a singleton-value scorer~\cite{zhou2026scout}, oracle-greedy (uses labels; an upper bound), and full information. (H1) Frontiers are concave: 25\% of rows recover most of the full-retrieval gain. (H2) Training on partial retrieval helps at low budgets. (H3) On \texttt{rel-avito}, past search results (which record clicks) are the most valuable lookups. (H4) Batch-aware policies beat case-local ones by more on \texttt{rel-event} than on \texttt{rel-avito}. (H5) The learned batch value beats the best heuristic and the singleton scorer. Analyses: ablations (training regime, stubs vs.\ dropping, batch vs.\ per-prospect credit), GraphSAGE vs.\ GAT vs.\ LightGBM, tables each policy fetches, and subsets (cold-start, sharing, list size).

\textbf{Preliminary results.} On \texttt{driver-top3} (validation AUROC, 3 seeds), the GNN with all rows scores $0.752 \pm 0.020$, 0.09 above LightGBM on the target row (0.661), and $0.749 \pm 0.010$ with a random 25\% of rows (rest dropped), consistent with H1. Training on such views did not help ($0.718 \pm 0.019$ at 25\%), so H2 is unsupported here; I will retest it with stubs and chosen lookups.
